# 4-B 고객·구독·입금 codex review

명령: `codex review --uncommitted`. 커밋 단위로 지적이 없어질 때까지 반복한다.

## 커밋 1: 스키마·구독 상태·입금·고객 API, 게시 결제 검사 (8회)

| 회차 | 등급 | 지적 | 처리 |
| --- | --- | --- | --- |
| 1 | P1 | 결제 검사(`requirePublishable`)가 어디서도 호출되지 않음 | 다음 커밋 예정이던 게시·롤백 검사를 이 커밋에 합침. 기존 검증 스크립트는 게시 전 입금 기록 |
| 1 | P1 | 유일한 결제를 취소하면 입금 대기인데 공개 유지 | 공개 여부를 매번 결제 상태에 맞춤(게시된 사이트는 활성·연체일 때만 공개) |
| 1 | P2 | 미래 기간·기간 사이 빈 날을 납부로 봄(MAX(period_end)) | 오늘을 포함하는 연속 납부 구간으로 계산(`coverage`) |
| 1 | P2 | 상태가 같으면 공개 상태를 맞추지 않음(운영자가 재개한 미납 사이트가 계속 공개) | 멱등 맞추기, 미납 사이트 재개는 409 |
| 2 | P2 | 스테이징 검증이 입금 없이 게시 | `verify-staging`에 입금 기록 |
| 2 | P2 | `2026-13-01` 같은 날짜가 500 | 파싱 결과가 유한한지 확인 |
| 3 | P1 | 자동 재개가 동시 해지를 되돌릴 수 있음 | 재개 갱신에 `cancelled_at IS NULL` |
| 3 | P2 | 동시 입금 확인 두 건이 같은 기간 | 기본 기간은 겹치는 결제가 없을 때만 넣고 재시도 |
| 4 | P2 | 낡은 결제 정보로 갱신하는 cron이 막 입금된 사이트를 중단 | 구독에 결제 리비전, 상태·공개 갱신을 리비전 조건부로 |
| 4 | P2 | 시작일만 주면 종료일이 엉뚱함 | 시작일부터 한 주기 |
| 5 | P2 | 렌더 중 결제 취소 시 첫 게시가 미납 공개 | 게시·롤백 뒤 결제 상태 재확인 |
| 5 | P2 | 동시 수정이 서로의 필드를 덮음 | 준 필드만 쓰고 날짜 순서는 SQL에서 현재 행 기준으로 확인 |
| 6 | P2 | 재개 중 결제 취소 시 미납 공개 | 재개 뒤 결제 상태 재확인 |
| 6 | P2 | 해지·재개가 리비전을 안 바꿔 낡은 갱신이 `cancelled`로 덮음 | 해지·재개도 리비전 증가(`billing_rev`) |
| 7 | P2 | 미래 선납 구간이 있으면 오늘 빈 구간을 건너뜀 | 기본 기간은 다음 선납 시작 전날까지 |
| 7 | P2 | cron에서 한 사이트 오류가 전체를 멈춤 | 사이트별로 오류 격리, 라우팅 재조정은 계속 |
| 8 | - | 지적 없음 | - |
