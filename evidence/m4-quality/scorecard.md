# M4 품질 점수표

4-E를 마친 뒤 사용자(운영자·사장님·방문자) 기준으로 점수를 잡고, 가장 낮은 항목부터 고쳐 다시 잰다. 멈추는 조건: 목표를 모두 넘기거나, 두 바퀴 연속 오르지 않거나, 최대 5바퀴.

측정: 공개 사이트·콘솔은 `scripts/measure-quality.mjs`(Docker, `metrics-<회차>.json`), 운영자 사용성은 코드를 모르는 프로덕트 오너 에이전트가 같은 "하루 업무" 과제(T1~T8)로 매긴 점수(`po-<회차>.md`), AI 제작은 headless 에이전트 실측(`m4-authoring/agent-run.md`).

## 기준선에서 찾은 것

방문자:
- SEO 감점: 문의 동의 링크 문구가 "자세히"뿐(link-text).
- 모범 사례 감점: favicon.ico 404가 콘솔 오류로 잡힘.
- LCP: 58KB 공용 CSS가 첫 표시를 막음(렌더 차단 약 120ms).

운영자(PO 하루 업무, 평균 4.4):
- 오늘 할 일이 결제 화면에만 있음. 운영자가 정지한 사이트, 시안 후속, 도메인 대기, 고객 미연결은 목록을 훑어야 앎. (T1 4점)
- 운영자 정지의 사유·정지한 사람을 볼 수 없음.
- 고객이 연결 안 된 사이트가 경고 없이 지나감. 같은 연락처의 고객이 있어도 연결을 제안하지 않음. (T3, T8 4점)
- "AI 도구 연결 방법"이 본문 작은 링크에만 있고, 상단 "지침"은 AI가 읽는 문서라 헷갈림. (T7 4점)
- 시안·도메인 안내문을 복사하기 전에 볼 수 없음.
- 결제 내역 기본 기간이 "최근 3개월"이라 "이번 달 합계"를 한 번 더 눌러야 함.
- 4-C에서 남은 것: "(작성 필요)" 경고가 위치를 말하지 않음, 내부 미리보기에 띠가 없음, 데이터 그리드 쪽 표시에 "of".

콘솔 성능:
- 첫 화면(사이트 목록)이 데이터 그리드(gzip 146KB)를 불러옴.

## 1회차 변경

- 공개·시안 페이지: 공용 CSS를 페이지 안에 넣음(첫 표시 전 CSS 요청 없음). favicon 선언. 동의 링크 "개인정보처리방침 보기".
- 콘솔 첫 화면 "오늘 할 일": 결제, 운영자 정지(사유), 시안(링크 없음·만료·확인 대기), 도메인 연결 대기·실패, 고객 미연결. 다섯 건 넘으면 더 보기.
- 사이트 목록을 가벼운 표로 바꾸고 데이터 그리드는 결제·고객 화면에서만 불러옴. 사이트 상세도 처음 쓸 때 불러옴.
- 공개 정지에 사유 입력. 개요에 누가·언제·왜 정지했는지 표시.
- 고객 미연결 경고와 "같은 연락처의 고객" 한 번에 연결.
- 시안 안내문 보기, 도메인 안내문 보기.
- "(작성 필요)" 위치를 경로로 표시. 내부 미리보기에 "내부 검수용" 띠.
- 상단 메뉴 "AI로 만들기", "지침"은 "제작 지침"으로.
- 결제 내역은 이번 달부터. 데이터 그리드 쪽 표시 "1–25 / 전체 62".

## 1회차 측정 메모

- LCP: 첫 화면 사진(42KB)과 하이드레이션 JS(98KB)가 같은 높은 우선순위로 대역폭을 나눠 썼다. JS에 `fetchpriority="low"`를 주자 레슨 2.19초 → 1.13초. CSS 인라인만으로는 LCP가 거의 변하지 않았다(렌더 차단은 사라짐).
- 콘솔 첫 화면: 처음 잰 "JS 364KB"는 로컬 wrangler가 압축하지 않은 전송량이었다. 측정을 gzip 기준으로 바로잡았다(`measure-quality.mjs`).
- 콘솔 100KB 목표: 공통 번들(react-dom, react-router, MUI 테마·AppBar, TanStack Query) 자체가 gzip 약 150KB(index 110 + 공유 38)라, 프레임워크를 바꾸지 않고는 닿지 않는다. 처음 목표가 이 바닥을 모르고 잡은 숫자였으므로 "기준선의 절반 이하(180KB)"로 고쳐 잡는다. 처음 183KB(49% 감소)였고, 알림 토스트(Snackbar)를 첫 알림 때 불러오고 오늘 할 일의 Grid를 CSS grid로 바꿔 179KB.
- 무거운 화면이 줄어든 이유: 데이터 그리드가 없는 화면(사이트·고객 상세)이 그리드 청크를 정적으로 불러오고 있었다. 원인은 고객 등록 창과 결제 수정 창이 그리드 화면 파일 안에 있었고, 번들러가 공용 MUI 모듈과 그리드 한국어 문구를 그리드 청크에 함께 묶은 것. 창을 별도 파일로 떼고 그리드는 자기 청크 그룹으로 분리했다.

## 2회차 변경 (1회차 PO 지적)

1회차로 목표를 모두 넘겼다. PO가 짚은 것 가운데 손이 적고 효과가 큰 것만 반영하고 확인한 뒤 마친다.

- 고객 화면에 "같은 연락처인데 고객이 연결되지 않은 사이트"와 연결 버튼.
- 연체·중단·청구 사이트에 "입금 요청 안내문"(금액, 이용 기간, 입금 계좌, 다음에 일어날 일). 선납한 청구 건과 납부 완료는 제외, 운영자 정지는 "담당자가 확인 후 다시 공개". 계좌는 콘솔 설정 `BILLING_ACCOUNT`, 비어 있으면 경고.
- 콘솔 공개 정지는 사유가 있어야 누를 수 있음.
- 입금 확인 알림에 상호·납부 기간·재공개 여부.
- 초안 저장 알림에 "사장님 시안 링크에도 바로 반영".
- 부가세 표기는 PRD 미결이라 그대로 둠(`po-round1.md` 메모).

## 결론

목표를 모두 넘겨 루프를 마친다(1·2회차 연속 PO 4.75, 성공 100%). 2회차 PO 지적 중 오늘 할 일의 정렬·정리성 작업 분리는 반영했다. 시드의 정지 사유는 데이터 문제라 시드에 사유를 넣었다. 남은 지적은 `po-round2.md` 처리 메모에 판단과 함께 남겼다.

남은 결정(사람이 정할 것):
- 받을 금액의 부가세 표기(공급가 30,000원인지 33,000원인지): PRD 미결 사항.
- 공개 중단 뒤 입금의 이용 기간 규칙(지금은 입금일부터)을 사장님 안내문에 어떻게 쓸지.
