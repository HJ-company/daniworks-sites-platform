# 4-E MCP 제작 도구 codex review

명령: `codex review --uncommitted`.

## 커밋 1: 지침 문서, 고객·사진 도구

| 회차 | 등급 | 지적 | 처리 |
| --- | --- | --- | --- |
| 1 | P2 | 서버 안내가 아직 없는 도구(customer_*, image_generate)를 부름 | 고객·사진 도구를 이 커밋에 포함, 이미지 도구 이름은 다음 커밋에서 추가 |
| 2 | P2 | 다른 사이트 설정이 쓰는 사진도 지워짐 | 모든 사이트의 버전에서 참조 확인 |
| 3 | P2 | 삭제 확인과 새 버전 저장이 경합 | 삭제 예약(한 문장으로 확인·예약), 버전 저장은 예약된 사진을 쓰면 거부(새 사이트는 배치 전체 취소) |
| 4 | P2 | 삭제가 끝나면 행이 사라져 예전 화면에서 지운 사진 저장 가능 | 행을 묘비로 남김, 같은 사진을 다시 올리면 되살림 |
| 5 | P2 | 삭제 중 재업로드가 파일을 덮었다 지워짐 | 삭제 중(deleting)과 완료(deleted) 구분, 삭제 중이면 업로드 거부 |
| 6 | P2 | 동시 삭제 두 건이 예약을 나눠 가짐 | 삭제 토큰으로 독점, 5분 넘게 멈춘 삭제만 이어받기 |
| 7 | P2 | 시험이 오래된 시각을 써서 이어받기로 통과 | 진행 중(지금 시각)과 이어받기(10분 전)를 따로 검사 |
| 8 | P2 | 사진 목록이 사진마다 전체 설정을 검색 | 이 사이트 사진을 언급한 버전만 한 번에 읽어 계산 |
| 9 | - | 지적 없음 | - |

## 단계 리뷰 후속: 업로드와 삭제의 직렬화 (5회)

| 회차 | 등급 | 지적 | 처리 |
| --- | --- | --- | --- |
| 단계 | P2 | 같은 사진의 동시 업로드가 삭제와 겹치면 파일 없이 성공 | 업로드가 파일을 쓰기 전에 행을 선점(uploading_at, 마이그레이션 0013), 삭제는 업로드 중이면 거부 |
| 1 | P1 | R2 쓰기 실패 시 선점이 남아 이후 업로드가 완료로 착각 | 실패하면 묘비로 돌려 다음 업로드가 전부 다시 씀 |
| 1 | P2 | 선점만 된 행을 완료로 반환 | 업로드 중이면 다시 시도 안내, 목록에서 숨김, 5분 넘게 멈춘 업로드는 이어받기 |
| 2 | P1 | 검증 스크립트 변수 이름 중복 | 이름 변경 |
| 2 | P2 | 되살리는 중인 사진을 예전 화면이 저장 가능 | 버전 저장은 업로드 중인 사진도 거부 |
| 3 | P2 | 멈춘 업로드가 이어받기·삭제된 뒤에도 성공 보고 | 완료는 소유권과 삭제 없음을 함께 확인, 삭제가 이어받으면 선점 해제 |
