# 2-8 커스텀 도메인 codex review

명령: `codex review --uncommitted`, 10회. 마지막 회차는 지적 없음. 도메인 수명주기는 외부 API, 비동기 검증, KV 최종적 일관성, 재렌더가 얽혀 있어 경합 지적이 많았다.

| 회차 | 등급 | 지적 | 처리 |
| --- | --- | --- | --- |
| 1 | P1 | KV 삭제 실패 시 행이 이미 지워져 재시도·재조정 불가 | 삭제를 `removing` 상태로 재개 가능하게, cron이 마무리 |
| 1 | P2 | 활성화 후 재렌더 실패가 영구히 남음 | `sites.origin_pending` 표시, cron 재시도 |
| 1 | P2 | 활성 도메인을 다시 확인하지 않음 | 활성 도메인 6시간마다 확인, 실패 시 서브도메인 복귀 |
| 2 | P1 | Cloudflare에서 지워진 호스트네임(404)을 일시 오류로 취급 | 404는 failed로 처리 |
| 2 | P2 | 상태 전환과 재렌더 표시가 따로 커밋 | `batch`로 함께 커밋 |
| 2 | P2 | 도메인 변경 전 버전으로 롤백하면 옛 canonical | 롤백 시 렌더 키가 다르면 그 버전만 재렌더 |
| 3 | P2 | 롤백 재렌더가 자산 버전을 올림 | **일부 기각**: 재렌더 HTML은 현재 렌더러가 만들므로 현재 클라이언트 번들과 짝이어야 한다. 대신 렌더할 때마다 현재 공용 자산 존재를 확인 |
| 3 | P2 | 도메인 유지보수의 `publish()`가 동시 게시를 되돌림 | 포인터를 건드리지 않는 `rerenderLive`로 교체 |
| 4 | P2 | 예전 활성 도메인이 14일 창 밖에서 영구 비활성 | `activated_at` 기록, 한 번 활성이던 도메인은 30분마다 계속 확인 |
| 4 | P2 | 새로고침이 삭제 중인 행을 되살림 | 이전 상태·CF ID 조건부 갱신, removing 행은 새로고침 안 함 |
| 4 | P2 | 겹친 재렌더가 옛 origin으로 끝나도 완료 처리 | 렌더 후 현재 origin 기준 렌더 키 확인, 매시간 origin 점검 |
| 5 | P2 | 같은 KV 키 연속 삭제가 초당 1회 제한에 걸림 | 재시도 쓰기 |
| 6 | P2 | 최종 정리가 라우팅 lease 밖에서 실행 | lease를 잡고 KV·행 삭제, 실패 시 cron |
| 6 | P2 | Cloudflare 삭제 전에 의사 기록 없음 | `removing` 먼저 기록 |
| 6 | - | (자체 추가) | 매시간 점검이 도메인 행 없는 고아 KV 레코드 삭제 |
| 7 | P2 | Cloudflare 장애 시 라우팅이 복귀하지 않음 | 삭제 의사와 라우팅·origin 재시도 표시를 함께 커밋 |
| 7 | P2 | 고아 판정이 오래된 스냅샷 기준 | 삭제 직전 D1 재확인 |
| 8 | P2 | 동시 재렌더가 같은 R2 키를 덮어 페이지가 섞임 | 렌더를 불변으로: render_id별 경로, D1에 한 문장으로 기록, 포인터가 render_id를 가리킴. M1 경로 호환 |
| 9 | P2 | quota 조회 `per_page=1`은 실제 API 최소값(5) 위반 | 5로 수정, mock도 5~50 강제 |

## 검증 (Docker, cf-mock)

- `verify-m2-domains.mjs` 30/30: 등록·안내(CNAME, 선택 TXT, 루트 도메인 포워딩 안내), 중복·형식·플랫폼 도메인 거부, quota, 검증 전 미서빙, cron 활성화, 커스텀 도메인 서빙·canonical·서브도메인 301(경로 유지)·브라우저, 롤백 origin, 중단된 재렌더 재시도, 활성 후 실패·외부 삭제 시 복귀, 예전 활성 도메인 자동 복구, removing 보호, origin 점검, 고아 KV 정리, Cloudflare 장애 중 삭제, 중단된 삭제 마무리, 삭제 후 복귀
- 전체 회귀: M1 18, 템플릿 28, 업로드 26, 라우터 14(M1 R2 경로 포함), 문의 24, 측정 8, MCP 19
- 실제 Cloudflare for SaaS(인증서 발급, 국내 등록업체 CNAME)는 스테이징에서 확인해야 한다.
