# M3 운영 결과 (로컬)

결론: 10곳을 운영하는 데 필요한 기능 중 데이터 없이 만들 수 있는 것은 모두 만들었다. 블로그 최신 글, 분기 리포트, 전체 재게시, 해지·인출, AI 홈페이지 전환이다. M2를 포함한 Docker 검증 259건이 깨끗한 상태에서 통과했다. 업종 템플릿 2~4번은 운영 자가진단 리드의 업종 분포 데이터를 받아야 만들 수 있다.

## 판단과 발견

- **블로그 카드와 하이드레이션**: 정적 HTML의 빈 영역에 라우터가 HTMLRewriter로 카드를 넣는다. `dangerouslySetInnerHTML` 영역이라 React가 비교하지 않아 카드가 유지된다(브라우저 검증). 네이버 이미지 요청에 Referer가 없는 것도 확인했다.
- **시각 비교 기준**: 같은 렌더끼리는 차이가 정확히 0%였다. 문구 한 줄 변경은 0.26%라 기준을 0.01%로 두었다. 크기가 바뀌면 항상 보류한다.
- **렌더 버전**: 공용 자산 해시만으로는 서버 렌더러 변경을 못 잡는다. `RENDER_VERSION` = 자산 해시 + 렌더러 소스·빌더 패키지 버전.
- **재게시 도구의 토큰**: 스테이지 화면 요청에만 관리자 토큰을 붙인다. 외부 이미지 요청에 토큰이 실렸는지 감시해 리포트에 남긴다.
- **완전 삭제**: cron이 하지 않는다. 보관 기간(`RETENTION_DAYS`, 기본 90일)이 지나고 운영자가 slug를 입력해야 한다. 삭제 중 상태를 먼저 잡고, 사이트에 쓰는 모든 경로가 이 상태를 확인한다. 중간에 끊기면 같은 요청으로 이어서 진행한다.
- **인출 zip**: 다른 서버의 도메인 루트에 올리면 그대로 열린다(브라우저 검증). 데이터는 페이지 단위로, 파일은 스트리밍으로 써서 메모리가 커지지 않는다.
